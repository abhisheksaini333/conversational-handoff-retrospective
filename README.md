# Conversational handoff retrospective

A runnable Rasa 2 assistant that hands a conversation to a simulated support desk **only after acknowledgement**, preserves an interrupted order form, and resumes it after completion. The original contribution is the durable, tested handoff protocol and its integration/evaluation harness.

## Run

Requirements: Python 3.8+ for dependency-free coordinator tests; Docker with Linux amd64 emulation for the pinned historical Rasa image (Apple Silicon works with Docker Desktop).

```sh
make test
make train
make up
make demo
make evaluate
make down
```

`make train` trains a tiny original synthetic dataset. `make up` generates private random credentials in ignored `.env`, starts Rasa at `127.0.0.1:4341` and the coordinator at `127.0.0.1:4340`. Allow Rasa to load the trained model before running the demo. `make down` preserves the named SQLite volumes for tickets and conversation trackers.

The demo checks an interrupted order form, acknowledged escalation, pause across a Rasa restart, guarded `/restart`, authenticated completion, form resumption, duplicate completion, an unavailable human desk and successful retry. `/intent` inputs deliberately isolate dialogue/protocol integration from classifier quality. The separate evaluation sends natural-language inputs to the trained model.

## Behavior

| Condition | Result |
|---|---|
| Explicit human request or low-confidence intent | Persist one pending ticket and a bounded transcript |
| Desk unavailable | Stay pending; do not claim a person accepted; retry safely |
| Desk acknowledges the same ticket ID | Persist human ownership and pause Rasa |
| Duplicate event | Replay its stored response; do not create a second ticket |
| Additional request while pending | Reuse the active ticket |
| Rasa restarts during human ownership | Restore paused tracker, ticket slot and form from SQLite |
| User sends `/restart` during human ownership | Keep ownership and remain silent |
| Human completes the active ticket | Resume Rasa and restore its interrupted form |
| Rasa unavailable during completion | Keep human ownership; retry the same completion event |
| Completion for an obsolete ticket | Reject rather than resume a newer conversation |

SQLite transactions protect ticket creation and receipts across process restarts. A separate persistent SQL tracker store protects Rasa's pause, slots and dialogue events. Session expiry is disabled; an explicit restart checks ownership before resetting the conversation. The synthetic desk also persists its acceptance by ticket ID. External resume delivery is **at least once**, not a distributed exactly-once guarantee. See [the architecture decision](docs/architecture.md) for boundaries and tradeoffs.

The evaluation uses eight development and eight held-out original synthetic utterances. It compares a fixed baseline threshold with a threshold selected using **only development examples**. It reports wrong routing and intent errors rather than claiming perfect accuracy. The offline calibrated threshold is not silently deployed; Rasa's configured fallback threshold is 0.6.

## Limits

Historical Rasa/dependency versions are retained for local reproduction, not recommended for internet-facing use. Ports bind only to loopback. The human desk is synthetic. The HTTP service requires a random bearer credential but is not a production multi-tenant gateway. SQLite serializes writers, and the bounded resume call holds a write transaction; a production service would use a durable outbox, per-conversation locks and a purpose-built human-channel bridge. Real transcripts require separate retention/access design; use synthetic data here.
